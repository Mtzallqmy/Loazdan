## قواعد مشتركة وحالات كل عائلة

Practice: ثلاث إجابات خاطئة عند ضغط «تحقق» → Lost مع شرح وإعادة محاولة بلا خصم تقدم سابق. لا عقوبة على حركة سحب أو تحرير حرف. wordsearch: المسار غير الصحيح يحسب فقط بعد زر تحقق؛ matching/order: فحص الترتيب الكامل يحسب محاولة واحدة؛ image_guess: الكشف تلميح مدفوع بالنقاط لا محاولة خطأ؛ sequence يقارن integer بعد تحويل الأرقام العربية إلى ASCII صراحة. لكل عائلة saveState يحفظ جميع الخلايا/البطاقات/المسارات/النص الحالي/حالة الكشف وhintIds وعدد المحاولات، لا مجرد شاشة رقمية.

تصميم wordsearch: 8 اتجاهات مستقيمة فقط، لا انحناء، ولا نفس كلمة مكررة بشكل عرضي غير مقبول؛ أداة النشر تسجل جميع المسارات المقبولة أو تعيد التوليد. matching في v1 bijection لا عدة إجابات لعنصر واحد. order يتطلب permutation وحيدة مع توثيق سبب الترتيب؛ عند تعدد ترتيب صحيح يحول اللغز إلى نسخة عقد جديدة بدل رفض إجابة صحيحة. anagram يحتفظ بهوية tile حتى عند تكرر الحرف؛ نوع الحرف المفقود يستخدم tiles كاملة مع fixedSlots في العقد: index صفري في ترتيب الإجابة، token مطابق للحل، بلا تكرار index ولا تثبيت كل الخانات؛ البلاطات الثابتة تُستبعد من التحريك بعد مطابقة multiplicity.

الوصول: للسحب أزرار «حرّك قبل/بعد»، وللشبكة تحديد خلية بالقارئ، ولألغاز الصور بديل وصفي لا يكشف الجواب قدر الإمكان؛ إذا كان الوصف يكشف الحل يقدم لغز بديل مكافئ بلا احتساب تنافسي. لا خسارة بسبب توقف التطبيق أو مكالمة. مستند GAME_ENGINE_SPEC هو مرجع النقاط والمحاولات.

التوسعات: visual_board يحتاج regions/hitboxes/constraints؛ matching_media يحتاج assetIds مع نفس matching semantics؛ cipher يحتاج alphabetMapping صريح وقابل للانعكاس؛ memory يحتاج shuffledPairs + revealedIds + matchedIds؛ prosody يحتاج originalVerse/segmentation/feet + مراجعة متخصص؛ context_groups يحتاج source-bound contexts + acceptedGroups؛ quest يحتاج DAG stages دون cycles وresume لكل stage. لا تُحتسب هذه الأنواع ضمن تسليم v1 أو اكتمال المرحلة الثانية.
