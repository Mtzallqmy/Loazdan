# المرحلة الرابعة — حالة التنفيذ الفعلية

آخر تحديث: 2026-10-29. الفرع المحلي والمعتمد: `stage-04-offline-content-sync`، مبني على المرحلة الثالثة. الحالة: تنفيذ واختبارات جارية، ليست مرحلة معتمدة مكتملة.

## الفحص الأولي

- محركات الألعاب الست موجودة ومستقلة عن Android؛ بناء المرحلة الثالثة واختباراتها 72/72 نجحت سابقًا في CI على commit `8c4e25aee571206fc45e259378c57faa91c0002c`، لكن اختبار الأجهزة توقف في المرحلة الرابعة من السيناريو عند العودة إلى الرئيسية. أُصلحت استعادة مسار التنقل محليًا؛ إعادة اختبار الجهاز مطلوبة.
- Room2 استخدم أعلى revision/version دون مؤشر نشط. كان هذا سيكشف الاستيراد الجزئي، ولذلك أضيفت عضوية كل إصدار ومؤشر نشط في Room3.
- التخزين القديم حفظ إيصالات النتائج لكنه لم ينفذ نقل المزامنة. الإيصالات محفوظة، مع جدول تسليم منفصل مرتبط بالحساب والجهاز.
- الحزم الأساسية فقط كانت قابلة للاستخدام؛ لا شبكة تنزيل ثانية داخل الألعاب. المنظومة الجديدة تستخدم المحتوى نفسه عبر المستودع.

## الشيفرة المضافة

- `core/content`: Manifest موقّع Ed25519 مع JCS، حدود الحجم/UTF8/المسارات والتبعيات، تنزيل متدفق HTTP Range، ETag، SHA-256، إعادة استخدام chunks موثقة، وفحص أنواع الملفات.
- `PackInstaller`: استيراد غير نشط، سجل تجهيز، fsync ثم rename على التخزين الخاص، تبديل مؤشر Room داخل معاملة، استرداد بعد الانقطاع، رجوع محلي مع الاحتفاظ بحد الإصدار الأعلى، وحذف يحفظ الجلسات والنتائج.
- `LocalContentRepository` و`PackDownloadWorker`: حالة مستديمة وتقدم حقيقي، أزرار إيقاف/استئناف/إلغاء، شبكة غير محسوبة افتراضيًا، مهام محدودة المدة وcheckpoint لكل chunk. التزامن الافتراضي واحد لحماية الكاش المشترك.
- `ContentScreens`: مكتبة/تفاصيل/تنزيلات/مساحة فعلية مع البحث والتصفية وتأكيد الحذف.
- `ProgressSync`: موافقة دمج صريحة بعد مصادقة موثوقة، تسليم ثابت المعرف والحمولة، دفعات محدودة، إعادة محاولة، دمج monotonic ومعاملة مؤشر السحب. المصادقة الافتراضية signed out؛ لا حساب وهمي.
- SQL004 وخادم المحتوى والمزامنة قيد فحص البناء والاختبارات. لا تُعد الترحيلات مطبقة في Neon حتى تسجيل اختبار وتطبيق فعليين.

## قرارات وحدود

1. صيغة المرحلة الأولى محفوظة: JSONL ووسائط مقسمة إلى chunks حتى 8MiB، دون ZIP أو تنفيذ SQL مستورد. الإصدار integer ثابت؛ لا تبديل إلى SemVer يكسر العقد.
2. لا تقبل الشبكة تحديث pack أساسي قديم بلا ترحيل ملكية صريح؛ يمنع ذلك اختفاء محتوى قديم أو فقد عضوية جلساته.
3. تنزيل الإصدار الكامل يعيد استخدام chunks المتطابقة؛ لا binary patches. النسخ السابقة محفوظة مع مراجعها. تنظيف الكاش يدوي وآمن؛ سياسة GC انتقائي تلقائية وتخزين نسخ متعددة تحتاج قياسًا.
4. القراءة الأولى محدودة إلى 200 لغز، ويطلب المستخدم المزيد. قياس مكتبة ضخمة/بحث شامل بفهارس محلية متخصصة ما زال مطلوبًا.
5. عنوان API ومفاتيح الثقة العامة لم تحدد للنشر. التطبيق يغلق التنزيل الخارجي عند غيابهما ويواصل اللعب المحلي. مفاتيح خاصة لا تدخل التطبيق.
6. لا مزود Object Storage سحابي معتمد حتى الآن، ولا نشر API عام أو تفعيل حسابات. هذه ليست خدمات تعمل في الإنتاج.
7. WorkManager يعمل في دفعات قصيرة قابلة للاستئناف؛ اختبار Android الحديث وحصص jobs وإشعارات UIDT/الخدمة الأمامية للمهام الطويلة مطلوب قبل اعتماد أداء تنزيل جيجابايت.
