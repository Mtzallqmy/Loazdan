# Semantic games

`matching` supports six semantic modes. Synonym, antonym and word_meaning use stable left/right IDs and explicit pairs. Intruder, context and difference use four typed options and correctId. The optional prompt supplies the instruction. The additive payload schema selects exactly one shape, rejects mixed shapes and restricts each variant to its corresponding interaction; the old left/right/pairs shape remains valid without a variant. Pair answers never depend on display positions.

Six debug levels demonstrate the modes, including an original context sentence about a mountain spring and an explicit listening/hearing distinction. No quotations or external publication text are used. All examples are original authored engineering drafts, unreviewed and unapproved. Linguistic review and rights clearance remain pending. No human reviewer or scholarly approval is represented, and these fixtures cannot ship in release.

Future vocabulary integration uses the existing `content.vocabulary` sense, reference_id, normalized_key and normalization_version, and optional root_id pointing to a source-linked `content.lexical_roots` record. Do not infer a unique root from the displayed spelling. A contextual word-meaning puzzle pins one reviewed sense and its source reference, places enough original or rights-cleared context in prompt, and includes that reference in sourceRefs. Roots can use the existing word_meaning pair interaction with an explicit root instruction; no new unimplemented variant is claimed. An editorial projection must preserve the source locator, edition/version and review/rights record when creating a puzzle. This is an integration contract, not a shipped vocabulary service or an approved Qur'anic/poetry dataset.
